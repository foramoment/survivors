**`src/engine/` — это отдельный движок, а не папка.** ~3400 строк, которые
ничего не знают про Survivors, плюс дизайн-система в `src/styles/`. Границу
сторожит `npm run lint:engine`: **ничто в `engine/` не имеет права импортировать
из `game/`**. Проверка заодно отвечает на вопрос «а это движок?» — если файл не
проходит, он не движок, и его надо либо вернуть, либо развернуть зависимость
(игра регистрируется в движке, не наоборот).

Ещё не перенесено, у каждого ровно одна связь с игрой: `Engine` (импортирует
`GameManager`), `I18n` (локали), `CollisionSystem` (`instanceof` Projectile/Zone
вместо проверки способности), `SpriteFactory` (шаблоны персонажей),
`PropField` и `StageBackdrop` (`StageData`).

**Оверлеи вынесены из GameManager** (был 1942 строки, половина — DOM).
Экран уровня берёт `GameManager` как **живой** host-интерфейс, а не снимок:
`player` пересоздаётся каждый забег. Итоги забега наоборот — чистая функция от
`RunSummaryData`; всё, что *меняет* состояние (ачивки, очки, лидерборд),
остаётся в `GameManager.endRun`.

## 🔁 Как устроен один кадр

Карта файлов выше отвечает «где что лежит», но не отвечает «что за чем идёт»,
а именно это приходится восстанавливать в голове каждый раз. Порядок в
`GameManager.update` — не случайный, в нём три места, где он уже был причиной
багов.

```
Engine.loop
  dt × juice.timeScale            (juice.update всегда получает РЕАЛЬНОЕ время)
  ─ state !== PLAYING → выходим целиком (пауза не рисует ничего)
  GameManager.update(dt)
    │
    1. player.update              ввод, движение, реген
    2. propField.resolve(player)  выталкивание из препятствий
    3. levelSpatialHash.clear/insertAll        ← ПЕРЕД оружиями
    4. weapons.forEach(update)    наведение и спавн сущностей
    5. enemy.speedMultiplier = hazardSpeed     ← сброс ПЕРЕД зонами
       enemy.resetForces()
    6. сепарация врагов (через хеш)
    7. entities.update            снаряды, зоны, лучи
                                  (здесь зоны домножают speedMultiplier)
    8. enemies.update(playerPos)  движение = speed × speedMultiplier
    9. CollisionSystem            попадания → damageSystem.dealDamage
   10. resolveContact             таяние игрока (см. ContactDamage)
   11. status.update              тики DoT, откат стана
   12. цикл смертей: killEcho → siphon → XP-кристалл
   13. difficultyDirector.update  спавн, волны, события арены
```

**Один список сущностей, а не проверка класса.** Всё, что спавнят оружия —
снаряды, зоны и чисто визуальные штуки — лежит в `GameManager.entities`.
Отрисовка выбирает проход по полю `Entity.layer` (`'ground'` под кристаллами,
врагами и игроком; `'air'` — над ними), а `instanceof` остался только в
`CollisionSystem`, где он решает **как** сущность сталкивается. Раньше он решал
ещё и то, попадёт ли сущность в мир вообще: `spawnEntity` молча выбрасывал всё,
что не `Projectile` и не `Zone`, — и Кровавый Тесак так и вышел в релиз,
нанося полный урон и будучи полностью невидимым.

**Три места, где порядок критичен:**

1. **Хеш строится до оружий (шаг 3).** Когда он строился после, оружие целилось
   по снимку прошлого кадра — а на первом кадре нового забега это были враги
   **прошлого** забега, застывшие там, где умерли. Отсюда был баг «нажал старт,
   и оружие сразу во что-то стреляет».
2. **`speedMultiplier` сбрасывается до зон (шаг 5).** Поэтому зоны и чёрная дыра
   просто *домножают* его, не заботясь об уборке за собой.
3. **Урон игроку отдельно от урона врагам (шаг 10).** `damageSystem` — только
   про врагов. Контакт идёт через `resolveContact` + `player.takeContact`, без
   глобальных i-frames.

**Путь одного удара**, если надо проследить цифру:

```
Weapon.update → onSpawn(entity) → GameManager.entities
  → CollisionSystem видит пересечение
  → damageSystem.dealDamage({ baseDamage, source, target })
      × might  × крит  × First Strike
      × (1 + corrosion.amp)                       ← внутри applyDamage
  → target.takeDamage → Enemy.isDead
  → колбэк damage-number → RunStats.recordHit
  → цикл смертей → killEcho / siphon / XP
```

`source` тащится через две ступени (снаряд → оружие → игрок), потому что
`DamageSystem.getPlayer` ищет владельца именно так — если новый снаряд не
проставил `source`, урон молча пойдёт без модификаторов.

## 🎲 Ключевые системы

### DamageSystem (Singleton)
**Файл:** `core/DamageSystem.ts`

Централизованный расчёт урона. **Весь урон** проходит через эту систему:

```typescript
// С модификаторами (crit + might):
damageSystem.dealDamage({ baseDamage: 10, source: weapon, target: enemy, position: enemy.pos })

// Без модификаторов (зоны с пре-калькулированным уроном, урон окружения):
damageSystem.dealDamage({ baseDamage: 50, source: null, target: enemy, position: enemy.pos, skipModifiers: true })
```

**Формула урона:**
```
finalDamage = baseDamage × might × (крит ? critDamage : 1) × (1 + firstStrike)
critChance  = player.stats.critChance
critDamage  = player.stats.critDamage (default 2.0x)
```

> **Единица урона = единица HP врага. Глобального множителя нет и быть не должно.**
>
> Здесь жил `GLOBAL_DAMAGE = 2` — окаменелость старого бага (`isCrit ?
> critDamage : 2`, из-за которого обычный удар удваивался, а крит на 1.5× бил
> *слабее*). Удвоение тогда сохранили как явную константу, чтобы не
> ребалансить. Цена оказалась выше: **любое число, которое UI мог показать,
> было вдвое меньше того, что видел игрок.** Карточка обещала «урон 36», в
> экран летело 95, и починить это на стороне UI было нельзя — врал сам
> конвейер урона.
>
> Константа удалена, `ENEMY_CONFIG.baseHp` понижен с 10 до 5 тем же коммитом:
> time-to-kill не сдвинулся, изменился только размер цифр. Заодно
> вдвое урезаны два числа на пути `skipModifiers` (метеорит в `ArenaEvents`,
> порог ачивки Overkill) — они старого удвоения не получали.
>
> Если когда-нибудь захочется «чтобы всё било сильнее» — это правится в таблице
> оружий или в `might`, где игрок это видит.

### ContactDamage
**Файл:** `core/ContactDamage.ts`

Урон **игроку** от врагов, стоящих на нём. Это отдельная система, не
`DamageSystem` (тот про урон врагам).

**Четвёртая редакция, и первая, которая не является ограничителем частоты.**
Три предыдущие пытались ограничить, *как часто* приходит урон, и все три
провалились, потому что сломан был *размер* удара:

1. **Глобальные i-frames.** Броня не работала, весь входящий урон был зажат в
   2 HP/с — одна мышь и сорок Вестников стоили одинаково.
2. **Непрерывная струя с `CROWD_CAP = 4`** и falloff `1/sqrt(k)`. Броня
   починилась, но сто врагов стоили как четыре, а капля 0.3 HP за кадр не
   читалась как урон. Реальный забег: 12019 килов, 5994 HP отхила, игрок стоит
   в центре арены.
3. **Укус на врага по своим часам + токен-бакет.** Толпа наконец начала
   масштабироваться — и числа взорвались.

Взорвались, потому что контактный урон умножался на четыре независимые шкалы
сразу: тир врага (×7.2) × время забега (×2) × intensity (×1.53) × стейдж
(×1.5) = **×33 за забег**. Замеры на релизной сборке: один тир-10 враг на
Нексусе кусал на 87 против реального пула в 115 HP, полное кольцо убивало за
0.18 с. Четвёртый ограничитель частоты провалился бы так же — ограничение
частоты не чинит поломку величины.

**Опора: здоровье — это бюджет на весь забег.** Пул игрока растёт примерно
×1.2 (75–150 по классам, +20 за пик). Ничто, растущее ×33, не сбалансировать
против этого ни при какой настройке. Поэтому контактный урон теперь **почти
плоский** (`ENEMY_CONFIG.baseDamage = 2.2`, ×1.08 за тир, **и `DifficultyDirector`
его больше не масштабирует вообще** — `getDamageMultiplier` удалён). Поздняя
игра давит количеством и HP врагов.

```
таяние/с = сильнейший из касающихся × sqrt(количество)
           × armorMultiplier(armor) × contactRamp(время)
```

- **Толпа под корнем, а не суммой.** Линейная сумма и породила жалобу «один
  враг ощущается слабо, а толпа отнимает несоизмеримо»: ×6 на кольце из шести
  и ×20 на куче из двадцати, и нет такого `baseDamage`, который устроил бы оба
  конца сразу. **Разгон уже делает работу, ради которой сумму заводили** — опасно
  в толпе не то, что их много, а то, что из неё не выйти, и `contactRamp`
  меряет ровно это. Корень оставляет толпу хуже (×2.45 на шести, ×4.5 на
  двадцати), не давая ей быть всей игрой. Убрать счёт совсем нельзя — тогда
  стена из двадцати стоит как касание одного, и это исходный баг i-frames в
  новой шляпе.
- **Ставку задаёт сильнейший из касающихся**, а не средний: Вестник, навалившийся
  на тебя, должен читаться как Вестник, а не размываться тремя мышами.
- **Капа на количество нет.** Геометрия ограничивает сама: вокруг игрока
  физически помещается 6–9 тел, а `touching` строится по реальному пересечению.
- **Разгон — это башня из LoL.** `contactRamp` идёт от 1 до `CONTACT_RAMP_MAX`
  (2.5) за `CONTACT_RAMP_FULL` (3 с) непрерывного контакта и сбрасывается за
  `CONTACT_RAMP_DECAY` (1.5 с). Занырнуть дёшево, стоять смертельно — и именно
  это позволяет базовому числу быть маленьким. Он же чинит провал редакции №2 в
  обратную сторону: стояние на месте не может переотхилить урон, который растёт
  от того, что ты стоишь.
- Разгон живёт **на игроке** (`Player.contactRampTime`), а не на врагах.
  Измеряется «сколько ты решил тут простоять», и смена состава толпы не имеет
  права его сбрасывать — на этом сломались все таймеры на врагах.
- **Броня — кривая `K / (armor + K)`, `ARMOR_K = 10`**, а не плоское
  вычитание. Каждое очко брони даёт одинаковую прибавку к эффективному HP
  (`эфф. HP = HP × (1 + armor/K)`), то есть броня и максимальное здоровье
  **перемножаются**. Плоская броня, наоборот, обнулялась к концу забега: 8
  стаков Void Shield снимали 8 с укуса в 87. Иммунитета кривая не даёт никогда,
  отрицательная броня (Берсерк, −2) проходит через ту же формулу и зажата
  далеко от полюса. Значение имеет только **отношение** к `ARMOR_K`: если
  крутишь константу, масштабируй вместе с ней все значения в `GameData`.
- `takeDamage` (с i-frames) остался для **дискретных** ударов: метеориты,
  схлопывание разлома. Не зови его для контакта — для этого `takeContact`.
  Броню он применяет через ту же кривую.
- Фидбек — `GameManager.emitContactFeedback` и `flushContactNumber`. Урон
  копится и печатается раз в `CONTACT_NUMBER_INTERVAL` (0.4 с): покадровое
  число — это мелькающие доли единицы, то самое «полоска ползёт, и непонятно
  почему», на чём провалилась редакция №2. **Никакой тряски камеры**: именно
  когда тебя обступили, надо видеть, где просвет.
- Отталкивание: игрока 55, врага 190. Обратное соотношение зажимало игрока в
  куче — толчки с разных сторон гасятся, и выйти было нельзя.

Числа, которые сторожит `contactDamage.test.ts` (пул 115, худший враг в игре):

| ситуация | цена |
| --- | --- |
| задеть одного врага | 4.7 HP/с — 24 секунды до смерти |
| пробежать сквозь кольцо (0.5 с) | 7 HP, 6% пула |
| кольцо из 6 на полном разгоне | 29 HP/с — 4.0 с |
| куча из 20 на полном разгоне | 53 HP/с — 2.2 с |

**`ENEMY_CONFIG.baseDamage` — единственный рычаг того, насколько страшен
контакт.** Больше на него ничто не умножается, в этом и был смысл переделки.
Первый заход поставил 1, и это игралось как «врагов вообще не боюсь»; выше
~1.8 ломается 75-хапэшный Маг Бури (тест сторожит).

> Тест намеренно проверяет **худший** случай в игре. Предыдущая версия
> проверяла тир 6 на первом стейдже без `damageScale` — самый лёгкий сценарий —
> и была зелёной, пока в релизе игрок умирал за 0.4 секунды.

### StatusEffects (Singleton)
**Файл:** `core/StatusEffects.ts`

Дебаффы живут **на враге**, а не на зоне — поэтому продолжают работать после
того, как враг вышел из облака.

```typescript
status.infect(enemy, { dps: 8, duration: 4, source: weapon,
                       contagious: true, spreadRadius: 90 });
status.stun(enemy, 1.4);
status.update(dt, enemies);   // тик урона (0.6с), вызывается из GameManager
status.onEnemyDeath(enemy);   // заразная инфекция прыгает на соседей
```

- `infection` — DoT через `damageSystem.dealDamage` (значит, might/crit
  работают). `contagious` = при смерти носителя заражает до 4 соседей,
  максимум 3 поколения, каждый прыжок слабее — иначе цепочка не сходится.
- `stun` — враг не двигается (`Enemy.update` выходит рано), но анимируется и
  получает урон. Боссам Mind Blast даёт только 25% длительности.
- **Стан не обновляется и имеет откат.** После стана враг получает
  `stunImmunity = длительность × STUN_RECOVERY_RATIO`, которая тикает только
  когда он уже отмер. Потолок — треть времени в стане, сколько бы источников и
  `duration` ни собрал игрок. Иначе Absolute Zero (он переназначает заморозку
  каждый кадр) при собранной длительности запирал всю арену навсегда.
- Индикаторы рисует `Enemy.draw`: споры на орбите + розовое кольцо стана.

### SpatialHash
**Файл:** `core/SpatialHash.ts`

Оптимизация поиска сущностей. Пространство делится на ячейки 100x100px.

```typescript
levelSpatialHash.clear();
levelSpatialHash.insertAll(enemies);
const nearby = levelSpatialHash.getWithinRadius(pos, radius);
```

### JuiceSystem (Singleton)
**Файл:** `core/JuiceSystem.ts`

Весь «game feel». Косметика, никакой игровой логики.

```typescript
juice.addTrauma(0.3);                 // тряска: offset = trauma², спад линейный
juice.hitStop(0.06);                  // заморозка мира на несколько кадров
juice.slowMo(0.3, 0.5);               // замедление времени
juice.flash('#ff0022', 0.3, 0.28);    // полноэкранная вспышка
juice.zoomPunch(0.7);                 // пружинный «удар» камеры
juice.shockwave(x, y, 300, '#fff');   // расширяющееся кольцо в мире
juice.pulseVignette(0.8);             // виньетка (опасность/босс)
```

**Правила:**
1. `Engine` умножает `dt` на `juice.timeScale`; сам `juice.update()` всегда получает **реальное** время.
2. Тряска через trauma — все источники делят один бюджет, стакинг невозможен (кап 1.0).
3. `juice.enabled = false` (Options → Screen FX) полностью отключает эффекты.
4. Старый `gameManager.shake(magnitude, duration)` сохранён и проксирует в trauma.

### AudioSystem (Singleton)
**Файл:** `core/AudioSystem.ts`

Чиптюн по схеме NES: PULSE1 (лид, duty + вибрато), PULSE2 (арпеджио или
контрмелодия), TRIANGLE (бас), NOISE (ударные). Тема стейджа сидирует
тональность, темп, **8-тактовую** последовательность аккордов и **пару**
8-нотных мотивов (вопрос + ответ).

**У каждого стейджа три трека и свой характер.** Профиль (`STAGE_MUSIC` в
`data/StageData.ts`) задаёт лад, полосу темпа, тональность, пул прогрессий и
«комнату» — задержку, драйв и потолок фильтра. Движок профилей не содержит:
их регистрирует игра через `audio.registerMusicProfile` (см. `Engine`), потому
что «Заброшенная Станция звучит индустриально» — факт про игру, а не про движок.

| Стейдж | лад | темп | комната |
| --- | --- | --- | --- |
| Пояс Астероидов | aeolian | 126–138 | открытая, светлая |
| Заброшенная Станция | dorian | 108–120 | тесная, грязная, тёмный фильтр |
| Void Nexus | phrygian | 138–152 | длинное холодное эхо |

Лад делает основную работу: dorian с повышенной секстой звучит настороженно и
механически, а фригийская пониженная секунда — это один полутон, который
превращает «грустно» в «неправильно».

Три трека стейджа — **братья, а не незнакомцы**: тот же лад, та же полоса
темпа, та же комната, транспонированы в родственные тональности (тоника,
терция, квинта), мотивы и прогрессии из одного пула. Выбор при старте
случайный, но **никогда не тот же, что в прошлый раз** — последний трек лежит
в `localStorage`. Чистый рандом повторяется примерно в трети случаев, а повтор
это ровно то, что игрок замечает.

Форма трека прописана вручную (`FORM` — 12 циклов по 8 тактов), а
`setMusicIntensity(0..1)` перекрывает её только на краях: тихо → intro,
босс → finale. Раньше секции выбирались одним порогом по heat, и трек
щёлкал между двумя паттернами — из-за этого казалось, что он зациклен.
Каждый 4-й цикл заканчивается барабанным филлом на целый такт.

Шина музыки: waveshaper drive → delay с обратной связью → lowpass, который
открывается с интенсивностью → компрессор. Никаких ассетов и библиотек.

### I18n (Singleton)
**Файлы:** `core/I18n.ts`, `core/Labels.ts`, `data/locales/`

Два вида строк — и это принципиально:

```typescript
t('pause.resume')                       // UI: английский лежит в locales/en.ts
tf('weapon.void_ray.name', w.name)      // данные: английский остаётся в GameData
```

Игровые данные (оружия, классы, бонусы, стейджи) **не дублируются** в `en.ts`:
английский берётся прямо из `GameData`/`StageData` как fallback, `ru.ts` —
единственная вторая копия. Обращаться к ним через `core/Labels.ts`
(`weaponName`, `classBonus`, `stageDesc`, …), а не через `.name` напрямую.

- Язык определяется как `localStorage` → `navigator.language` → `en`.
- Экраны строят DOM в `enter()`, поэтому смена языка = `screenManager.reload()`
  (подписка в `Engine`). Игровой экран исключён — перезаход бы рестартнул забег;
  `GameManager` пересобирает свой оверлей паузы сам.
- Пропущенный ключ падает по цепочке ru → en → сам ключ, а не кидает ошибку.
- Кириллица в `PixelFont` есть (баннеры арены, слоган меню). Одинаковые с
  латиницей буквы (А В Е К М Н О Р С Т Х) — алиасы, Ё = Е. Тест
  `i18n.test.ts` проверяет, что для каждого символа canvas-строк есть глиф.

## 📊 Статы игрока

**Файл:** `core/PlayerStats.ts` + `entities/Player.ts`

| Стат         | Default | Описание                              |
| ------------ | ------- | ------------------------------------- |
| `might`      | 1.0     | Множитель урона                       |
| `area`       | 1.0     | Множитель радиуса оружий              |
| `cooldown`   | 1.0     | Множитель кулдауна и **интервала тика зон** (меньше = быстрее) |
| `speed`      | 1.0     | Скорость снарядов                     |
| `duration`   | 1.0     | Длительность эффектов                 |
| `moveSpeed`  | 1.0     | Скорость передвижения (база `Player.speed` = 190 px/s) |
| `magnet`     | 100     | Радиус притяжения XP кристаллов, **+2 за уровень** (перка нет) |
| `growth`     | 1.0     | Множитель получаемого XP              |
| `armor`      | 0       | Кривая `K/(armor+K)`, K=10 — снижение всего входящего урона (см. ContactDamage) |
| `regen`      | 0       | HP/сек регенерации                    |
| `critChance` | 0       | Шанс крита. Базы нет: крит собирается перками или классом |
| `critDamage` | 2.0     | Множитель крит урона                  |
| `shield`     | 0       | Максимум буфера поглощения (Кинетический Отражатель) |

> Стат `tick` удалён вместе с перком Rapid Tick: интервал тика зон теперь
> умножается на `stats.cooldown`. Старая формула была `interval − tick`, и на
> третьем пике упиралась в пол — следующие пять карт не делали ничего.

### Кривая опыта: сначала геометрия, потом прямая

**Файл:** `entities/Player.ts` → `XP_LINEAR_FROM` (40), `XP_LINEAR_STEP` (250)

До 40-го уровня — та же кривая, что и всегда (`×1.1 + 6`, старт с 4). Дальше
цена растёт **фиксированным шагом**, потому что доход по опыту компаундиться не
может: он зажат `MAX_ENEMIES = 400` и тем, как быстро билд это удаляет.
Геометрическое требование против сублинейного дохода расходится **по
построению**, а не при неудачной настройке.

Замер на реальном 15-минутном клире Void Nexus: 69-й уровень стоил 35 893 опыта
— около 1100 килов, **93 секунды**, и следующий на 10% дороже. Отсюда жалоба
«в лейтгейме становится скучновато»: игра перестаёт выдавать решения.

Шаг 250 — это тот самый инкремент, который геометрическая кривая **уже имела**
на 40-м (2437 → 2686). Поэтому в точке перехода нет излома: кривая не
удешевляется, она перестаёт ускоряться. Что даёт замена на тех же двух забегах:

| забег | было | стало |
| --- | --- | --- |
| смерть на 9:00 (55 487 опыта) | 49 | **49** — не изменилось ничего |
| победа 15:24 (355 140 опыта) | 68 | **83** |

Первое так же важно, как второе. Ранняя и средняя игра были настроены и в
жалобу не входили; десятиминутный забег по Поясу Астероидов до перехода почти
не доходит. Это правка длинных забегов на сложных стейджах и больше ничего.

> Побочный эффект, который стоит помнить: до этой правки **Vampiric Link был
> математически убыточной картой** — шесть пиков давали +60% опыта, что на
> геометрической кривой стоило около пяти уровней. На линейном хвосте те же
> шесть пиков дают уже больше десяти. Перк починился сам, трогать его не надо.

### Перки: плоское стакание + свой кап у каждого

**Файлы:** `data/GameData.ts` (`POWERUPS`), `core/UpgradePool.ts`

Каждый пик стоит ровно `value`, каждый перк объявляет свой `maxStacks` и после
него перестаёт выпадать. Раньше была общая кривая ×1.25 за стак с общим капом
8 — то есть **×19.84 к базе** у любого перка, что и превращало «+18%
длительности» в +357%, а «+10% скорости» — в +198%.

Потолки, которые держат билд конечным (тест `upgradePool.test.ts` их сторожит):

| Перк | стат | итог на капе |
| --- | --- | --- |
| Plasma Core | `might` | +25% (5 пиков) |
| Targeting HUD | `critChance` | 40% |
| Berserker Rage | `critDamage` | 2.0 → ×4 |
| Cooling System | `cooldown` | ×0.60 |
| Temporal Flux | `duration` | ×1.8 |
| Chain Reaction | `area` | ×1.64 |
| Phase Shift | `moveSpeed` | +15% (3 пика) |

Скорость движения не даёт **ни один класс** — игрок и так быстрее самого
быстрого врага (190 против 120), а сверху этого блэкаут на станции (+30%
врагам) переставал что-либо значить.

### Перк не имеет права быть удобством

**Gravity Well удалён, радиус притяжения теперь +2 за уровень.** Кристаллы не
исчезают вообще (см. `CrystalField`), поэтому дальность магнита покупала
*удобство* и ничего кроме — но стояла в раздаче с тем же весом, что и урон. В
замеренном забеге игрок отдал ей **три пика из девятнадцати**.

Правило общее: если карта не меняет ни одного решения в бою, её нельзя чинить
числом. Её надо либо убрать из пула, либо раздать даром. К 50-му уровню
магнит набирает +98 — почти четыре старых пика, — и ни один забег больше не
проигрывает за отказ платить за комфорт.

### Кинетический Отражатель: буфер, а не третий вид живучести

**30 HP за три пика.** Броня — это процент, реген — струйка между боями; оба
поощряют *не быть здесь*. Буфер, который заряжается только вне контакта, делает
**занырывание** повторяемым: потратил, проходя сквозь толпу, вернул, оторвавшись.

- Правила и числа — `SHIELD_RECHARGE_DELAY` / `SHIELD_REFILL_TIME` в
  `core/Tactics.ts`, состояние — `Player.shield`, поглощение — `Player.absorb`
  (через него проходят **и** контакт, **и** дискретные удары).
- **Не заряжается, пока по тебе прилетает** — иначе это «стоять в толпе
  бесплатно», ровно тот провал, ради которого контактный урон переписывали
  четыре раза.
- **Не трогает `contactRampTime`.** Разгон идёт от того, что тебя касаются, а
  не от того, дошло ли до здоровья: под щитом ты покупаешь время, а не
  неуязвимость, и когда он лопнет, множитель уже полный.
- Задержка (3 с) намеренно **длиннее** `CONTACT_RAMP_DECAY` (1.5 с): иначе
  оптимальной игрой становится дрожать на кромке толпы.
- «Урон получен» и цифра над головой считают **то, что сняли с полоски HP**, а
  не входящий урон. Секунды в контакте считаются всегда — кадр под щитом всё
  равно проведён в куче.

Маленький он не от осторожности, а по замеру: победный 15-минутный Нексус взял
1374 урона при пуле 190 и отхилил 1261 из них тремя пиками Nano-Repair, на
классе с **отрицательной** бронёй. Живучесть уже решена; щедрый щит сверху не
добавил бы решения, а убрал бы то, которое ставит контактная модель.

## ⚔️ Система оружий

### Иерархия классов

```
Weapon (abstract)
├── ProjectileWeapon (abstract) — стреляет снарядами
│   └── Переопределяй createProjectile() для своих типов снарядов
├── ZoneWeapon (abstract) — создаёт зоны урона
│   └── Переопределяй spawnZone() для своих типов зон
└── Кастомные (VoidRayWeapon, LightningChainWeapon и т.д.)
```

### Типы снарядов (`weapons/base/Projectile.ts`)

| Класс                   | Описание                   |
| ----------------------- | -------------------------- |
| `Projectile`            | Базовый летящий снаряд     |
| `BouncingProjectile`    | Отскакивающий (ChronoDisc) |
| `SingularityProjectile` | Чёрная дыра, тянет врагов  |
| `PlasmaProjectile`      | Взрывается при смерти      |
| `OrbitingProjectile`    | Вращается вокруг владельца |
| `LobbedProjectile`      | Летит по дуге к цели       |

### Типы зон (`weapons/base/Zone.ts`)

| Класс                  | Описание                         |
| ---------------------- | -------------------------------- |
| `Zone`                 | Базовая зона урона               |
| `FrostZone`            | Изморозь на полу: неровная кромка, «пальцы» инея, слой льда |
| `AcidZone`             | Кислотная лужа с пузырьками      |
| `BurningTrailZone`     | Горящая земля (Разорение, Cluster Bomb) |
| `SporeZone`            | Грибница: нити мицелия + споры, **растёт всю свою жизнь** |
| `NanobotCloud`         | Следует за игроком               |
| `MindBlastZone`        | Пульсирующая пси-волна           |
| `DelayedExplosionZone` | Задержка + взрыв (OrbitalStrike) |
| `AbsoluteZeroZone`     | Ледяная плита: трескается к концу, потом разлетается |

**Три правила зон** (`weapons/base/Zone.ts`):

1. **Рост за всю жизнь.** `growOver(from, to)` — множители радиуса в момент
   падения и в момент смерти. Зона растёт **всю свою длительность**, а не за
   0.3 секунды: четверть секунды — это не «кислота растекается», это спрайт,
   который масштабируется.

   | Зона | from → to |
   | --- | --- |
   | FrostZone | 0.265 → 1 |
   | AbsoluteZero | 0.35 → 1 |
   | AcidZone | 0.4 → 1 |
   | BurningTrail | 0.55 → 1 |
   | StaticField | 0.5 → 1 |
   | SporeZone | 1 → **1.5** |
   | FungalBloom | 1 → **2** |

   `baseRadius` — это то, что запросило оружие (`area × stats.area`), то есть
   перки на площадь увеличивают **стартовый** размер, а рост идёт поверх.
   Геометрия печётся против `baseRadius`, а в `draw` умножается на `growScale`.
   По умолчанию 1→1 — телеграфленные взрывы (орбиталка, пси, плазма) появляются
   сразу, ты уже посмотрел на прицел.

2. **Никаких обводок.** Ни одна зона не обводит себя контуром. Градиент уходит
   в ноль **до** края силуэта, а кромку рассказывают частицы
   (`particles.emitZoneEdge`) — дымка, которая редеет, а не линия, которая
   обрывается. Обведённый круг на полу читается как маркер выделения; хуже
   того, когда зона выцвела, кольцо остаётся единственным, что видно.

3. **Пол на слоу — `Zone.SLOW_FLOOR = 0.35`.** Мягкий контроль может
   масштабироваться, но 90% слоу на всю арену — это стан без правила отката из
   `StatusEffects`. Никто не ползёт медленнее трети своей скорости.

### Frost Nova: поле по одному за раз

**Станит только эволюция.** База — чистое замедление (слоу это её работа: он
покупает дистанцию). Absolute Zero замораживает пойманных **в момент падения**,
а дальше держит их глубоким слоу и в конце раскалывается. Плита больше не
пере-станит каждый кадр — это была та самая форма, ради которой в
`StatusEffects` пришлось заводить правило отката.

Кулдаун Frost Nova **не начинает тикать, пока её поле не растаяло**
(`activeField` в `FrostNovaWeapon`). С обычным кулдауном `duration` и
`cooldown` тянули в разные стороны, пока три новы не начинали лежать друг на
друге — это уже не оружие, а обои, и вся арена оказывалась замедлена навсегда.
Привязка к жизни поля делает все статы одним и тем же: сколько времени лёд
лежит. Падение заряда само по себе **станит** пойманных и бьёт бурстом, и
только потом поле начинает замедлять — «заморозил, потом придержал».

### Типы лучей (`weapons/base/Beam.ts`)

| Класс            | Описание                                  |
| ---------------- | ----------------------------------------- |
| `Beam`           | Простой визуальный луч                    |
| `ChainLightning` | Молния: удар с неба + прыжки по врагам    |

`VoidRayBeam` и `SweepingLance` удалены. Оружие Странника Пустоты переписано
**дважды** и оба раза по одной причине: прямой луч по линии был механически
нормальным и мёртвым на вид, а ведомый лазер с зигзагами был самой сложной
вещью в пуле и «наносил урон, но ни разу не ощущался круто».

Что было упущено: **это первый класс в списке**. Его берут новички, и его
задача — учить игре. Поэтому теперь это `VoidBolt` — быстрый болт, прошивающий
пару тел и рвущий небольшой разрыв (`VoidRip`) там, где остановился. Разрыв —
единственная экзотика: он слабо тянет и перемалывает, из-за чего важно, **где**
болт встал. Эволюция — три болта веером.

> Урок общий: «скучно на бумаге» и «скучно в руках» — разные вещи, и стартовое
> оружие первого класса должно проигрывать в изобретательности, а не выигрывать.

**ChainLightning** прыгает **по одному врагу за `hopInterval`**, а не за один кадр:
геометрия каждой дуги «запекается» при создании (не рандомится каждый кадр),
первый сегмент падает с неба. Настройки: `chainRange`, `hopInterval`,
`damageFalloff`, `maxChainLength`, колбэки `onHit` и `onArc` (последний —
для AoE-следов эволюции).

### Эволюция оружий

При достижении **уровня 6** оружие эволюционирует:
- `evolved = true`
- `damage *= 2`
- `area *= 1.3`
- Новое имя и эмоджи из `WEAPONS[id].evolution`

**Важно:** Эволюция НЕ уменьшает cooldown — **и если она умножает число
снарядов, то платит кулдауном.** Иначе «три колбы вместо одной за тот же
кулдаун» — это ×3 выхлопа бесплатно, поверх ×2 урона от самой эволюции.

| Оружие | что даёт эволюция | налог на КД |
| --- | --- | --- |
| Acid Pool | 3 колбы + сильнее коррозия | ×1.6 |
| Plasma Grenade | 5 канистр + горящая земля | ×1.5 |
| Orbital Strike | 4 снаряда + тяжёлый добивающий | 4.0 → 9.0 с |
| Mind Blast | каскад на 4 цели | ×1.6 |
| Void Bolt | 3 болта веером + глубже прошив | — |
| Lightning / Phantom Slash / Plasma Cannon / Singularity | — | ×1.2 / ×1.25 / ×1.4 / ×1.35 |

### Что даёт уровень оружия

Апгрейд по умолчанию — только ×1.2 урона. Но у оружия, где голая цифра не
читается, есть **структурный** рост (иначе прокачка не ощущается):

| Оружие | за уровень |
| --- | --- |
| Plasma Grenade | +1 канистра каждые 2 уровня (1 / 2 / 3), **каждая бьёт в полную силу** |
| Plasma Cannon | +1 осколок за уровень (5 → 10, +3 за эволюцию) |
| Lightning | +1 прыжок за уровень (+6 за эволюцию), потолка нет — урон сам затухает по прыжкам |
| Frost Nova | +9% радиуса поля за уровень (слоу упирается в 62% на 5-м) |
| Acid Pool | +2% коррозии за уровень, **и это не сбрасывается эволюцией** |
| Orbital Strike | +1 снаряд в залпе каждые 2 уровня, второй уже на 2-м (+3 за эволюцию); снаряды **вылетают по очереди**, иначе прицелы хоронят арену |
| Spore Cloud | +бюджет продления: каждая смерть на грибнице продлевает её на 1 с, потолок растёт с уровнем |
| Mind Blast | +20% радиуса (стартовый радиус специально уполовинен до 60) |
| Void Bolt | +1 прошиваемое тело за 2 уровня |
| Blood Cleaver | +7% радиуса за уровень |
| Phantom Slash / Chrono Disc / Lightning | +1 цель / диск / прыжок |
| Spore Cloud / Orbital / Nanobot / Singularity | +радиус |
| Acid Pool / Frost Nova | +коррозия / +слоу (с потолком) |

### Сигнатурные оружия

**Файл:** `core/UpgradePool.ts` → `SIGNATURE_WEAPONS`, `canOfferWeapon`

Стартовое оружие класса принадлежит **только ему** — другим классам оно в
пуле уровней не выпадает. Шесть из четырнадцати оружий разобраны классами,
оставшиеся восемь — общий пул.

Смысл: «какой персонаж» перестаёт означать «с чего я начну» и начинает
означать «что я могу получить только здесь». Цепная молния бывает только у
Мага Бури; хочешь Кровавый Тесак — играешь Берсерком. Это же даёт
опору перкам класса: связку «стат + оружие» больше нельзя размыть, вытянув то
же оружие другим персонажем.

Карта строится из `CLASSES` (`weaponId → id`), поэтому разъехаться не может.
Уже взятое оружие исключение не трогает — своё сигнатурное надо качать.

### Вес оружия в раздаче падает к середине

**Файл:** `core/UpgradePool.ts` → `ownedWeaponWeight`

Два забега одного игрока, и это самая полезная пара чисел, которая у проекта
есть:

| распределение пиков | результат |
| --- | --- |
| 29 из 48 в оружие, 19 в перки | 48k DPS, смерть на 9:00 |
| 27 из 67 в оружие, **40 в перки** | 284k DPS, клир 15:24 |

**Оружия складываются, перки умножаются.** Пятое оружие — это пятый источник
урона; максимальная Cooling System — это +67% ко всем сразу. Значит начиная с
середины забега предельный перк бьёт предельный уровень оружия. Плоский вес 9
означал, что игрок с пятью оружиями видел оружейную карту примерно в **половине**
всех карт: раздача вела к худшему выбору, и проигравший забег — тот, который её
послушался.

Поэтому вес падает там, где оружие в раздаче нуждается меньше всего, и **только**
там:

| уровень оружия | вес | почему |
| --- | --- | --- |
| 1–2 | 9 | только что взято и правда слабое; голодом его морить нельзя — так пул когда-то требовал ~60 уровней на эволюцию |
| 3–4 | **6** | тот самый участок, который вытеснял весь пул перков |
| 5 | 14 | выплата за эволюцию должна оставаться достижимой; она никогда и не была сломана |

Замер на фикстуре теста: доля оружейных карт 50.75% → 45.0%. Гарантия «хотя бы
одна карта своего оружия в раздаче» осталась — она чинит настоящую проблему
(без неё конкретное оружие выпадало ~в 10% раздач), просто больше не сидит
поверх веса, который и так вёл в ту же сторону.

### Апгрейд оружий

```typescript
// Weapon.ts - базовый upgrade()
upgrade(): void {
    this.level++;
    this.evolved = this.level >= 6;
    this.damage *= this.damageScaling; // 1.2x
}
```

### Логика спавна и адаптивная сложность

**Файлы:** `core/DifficultyDirector.ts` + `GameManager.ts` → `spawnEnemy()`

Спавном управляет **DifficultyDirector** (singleton `difficultyDirector`):
- Спавн через аккумулятор (независим от FPS): `spawnRate = min(30, (2 + gameTime/45) × intensity)`
- **intensity** (0.6–3.0) адаптируется раз в секунду по HP игрока и скорости зачистки (kills/sec vs spawns/sec)
- HP врагов: `(1 + gameTime/240) × (0.75 + 0.25 × intensity)` × `stage.hpScale` — **кап 3x убран**
- **`stage.hpScale` вводится не сразу, а за первую минуту** (`STAGE_SCALE_RAMP`), и
  **опыт за врага едет по той же кривой**. Без второго первая минута самого
  сложного стейджа стала бы самым быстрым способом качаться: `xpValue` считается
  только от тира, а пул Void Nexus начинается с тира 3 (×3 опыта). Это **не**
  «опыт пропорционален HP» — такая версия даёт петлю через `effectiveTime`
- Контактный урон **не масштабируется вообще**: `getDamageMultiplier` удалён, а
  `stage.damageScale` к нему не применяется. Его собственный комментарий всегда
  говорил «поздняя игра давит количеством, а не укусом одного» — теперь это
  правда и в коде. Здоровье игрока — бюджет на весь забег (см. ContactDamage)
- **HP и урон считаются от «позднейшего из» — таймера и уровня игрока**
  (`effectiveTime`, один уровень = 8 секунд). Дыра, которую это закрывает: на
  сложном стейдже первых врагов не убить, поэтому их кайтят; кристаллы больше
  не пропадают, так что куча XP копится без риска, а один взмах превращает её в
  пять уровней — против врагов третьей минуты. Сам приём остаётся (копить толпу
  и снести её — хорошее решение), он перестаёт быть **бесплатным**. При обычном
  темпе (уровень раз в ~10 с) член по времени всегда больше, так что ничего не
  меняется.
- Elite: шанс растёт со временем и intensity, кап 8%
- События на границе волны (каждые 60с): **burst** (кольцо врагов, 8 + wave×4) и **miniboss** (×12 HP, ×2 радиус, HP-бар)

Выбор типа врага — из `stage.enemyPool` (индексы в ENEMIES), микс 90%/10% → 10%/90% внутри волны, как раньше.

### Стейджи

**Файлы:** `data/StageData.ts`, `ui/screens/StageSelectionScreen.ts` (screen id `level_select`)

3 стейджа с собственным пулом врагов, темой фона, множителями и длительностью. По истечении `duration` спавнится финальный босс (miniboss ×3 HP); его смерть = победа (`showVictory`).

Каждый стейдж несёт палитру `visuals: StageVisuals` (цвет пустоты, небулы,
звёзд, пыли, hue пола, экранный свет + виньетка, `flicker`/`pulse`). Её читает
`core/StageBackdrop.ts` — единственное место, где рисуется фон арены:

```
far   (0.22×)  запечённая плитка небула+звёзды        ← ctx.createPattern
stars (0.22×)  ~160 живых мерцающих точек
floor (1.00×)  плитка пола, полупрозрачная (швы вырезаны destination-out)
near  (1.45×)  пыль и обломки перед игроком
```

`drawLighting()` (screen-space, вызывается из `GameManager.draw` после снятия
zoom-трансформа) кладёт цветную заливку + виньетку; `flicker` даёт аварийные
лампы станции, `pulse` — «дыхание» Нексуса. Всё анимированное отключается
вместе с `juice.enabled` (Options → Screen FX).

### Препятствия (PropField)

`props: StageProps` в стейдже задаёт стиль (`rock`/`crate`/`crystal`),
плотность и разброс радиусов. `core/PropField.ts` генерирует их **по чанкам
520×520** из сида `(theme, cx, cy)` — та же клетка всегда даёт те же
препятствия, хранить/стримить нечего, дальние чанки просто выбрасываются.
Круг радиусом 300 вокруг начала координат всегда чист (спавн игрока).

Это единственная часть «глубины уровней», которая влияет на геймплей:

```typescript
propField.update(player.pos);            // стрим чанков
propField.resolve(player);               // выталкивание из препятствия
propField.resolve(enemy, player.pos, enemy.speed * 0.7, dt); // + скольжение вдоль
```

Враги скользят по касательной в сторону игрока — иначе они утыкаются в камень
и стоят. Боссы препятствия игнорируют (проламываются). Снаряды и зоны летят
поверх: препятствия не блокируют урон.

### События арены (ArenaEvents)

`DifficultyDirector` шлёт `{ type: 'arena' }` раз в 30–60с (первое — на 45с,
константы в `ArenaSchedule`), `GameManager` превращает это в `stage.event`:

| Kind       | Стейдж     | Что делает                                                     |
| ---------- | ---------- | -------------------------------------------------------------- |
| `meteors`  | Asteroids  | Метеориты с наземным телеграфом → урон врагам и 8% HP игроку   |
| `blackout` | Station    | Свет гаснет на ~10с (`stageBackdrop.blackout`), враги +30% скор. |
| `rifts`    | Void Nexus | 4 разлома открываются и льют врагов, пока не схлопнутся          |

Правила: **сначала телеграф, потом урон** (баннер + кольцо/спираль), одно
событие за раз, урон окружения — доля от max HP (`hazardDamage`), чтобы
хазарды не обесценивались к концу забега.

### Гравитация Чёрной Дыры

`BlackHoleZone` — единственное, что меняет **скорость** врагов, а не только их
позицию:

- **За горизонтом** — `speedMultiplier = 0`. Это не стан: ни отката, ни
  иммунитета, ни правила из `StatusEffects`. Дыра держит то, что в неё упало,
  пока не схлопнется. (Раньше враги спокойно шли сквозь чёрную середину.)
- **Снаружи** — `GRAVITY_ASSIST = 0.4` с затуханием к кромке, со знаком по
  скалярному произведению курса врага и направления на дыру. Идёт к тебе
  *сквозь* дыру — разгоняется; выкарабкивается наружу — вязнет. Поэтому
  поставить дыру между собой и толпой — это размен, а не бесплатный контроль.

Порядок важен: `GameManager` сбрасывает `speedMultiplier` каждый кадр **до**
обновления сущностей, поэтому зона просто домножает.

### Kill Echo: процент от **текущего** HP цели, и он не может добить

Три редакции, и рассуждение стоит помнить целиком:

1. `0.55 × макс. HP трупа` — жирное тело становилось бомбой, а убитые эхом
   катали своё эхо. Экран вычищался целиком.
2. `0.18 × макс. HP цели` — чинит всплеск от жирного трупа, но остаётся дыра:
   боссы ходят в окружении мелочи, и каждая убитая мелочь снимала фиксированные
   18% с **огромного** максимума босса. Босса плавили, фармя его свиту.
3. **Процент от текущего HP** (как Blade of the Ruined King в LoL) — урон
   *убывает* по мере ослабления цели, то есть ровно наоборот тому, что нужно
   каскаду. Боссам ещё и `KILL_ECHO_BOSS_RESIST` (четверть).

Сверху — **эхо никогда не наносит смертельный удар** (`min(hp × share, hp − 1)`).
Значит эхо не создаёт трупов, значит не создаёт новых эхо: каскад невозможен
*по построению*, а не «маловероятен». Перк смягчает толпу, добивают твои оружия.
Поджиг уцелевших убить может — он разрешается за секунды через `StatusEffects`,
а не внутри кадра.

**Общее правило:** любой триггер на смерть проверяй на самоподдержку. У заразной
инфекции это `MAX_GENERATIONS` с самого начала, у Kill Echo пришлось добывать
кровью.

### First Strike

Единственный множитель урона, который не может кормить каскад: применяется
только к **первому** удару по нетронутой цели (`DamageSystem.openerBonus`),
поэтому не помогает добивать и не складывается сам с собой. Меняет прицеливание:
выгодно разносить урон по свежим телам, а не доливать в уже умирающих.

### Сепарация врагов

Враги не пересекаются благодаря силам сепарации (SpatialHash):

## 🎯 Паттерны кода

### Создание нового оружия

```typescript
// weapons/implementations/MyWeapon.ts
import { ProjectileWeapon } from '../base';
import type { Player } from '../../entities/Player';

export class MyWeapon extends ProjectileWeapon {
    name = "My Weapon";
    emoji = "🔫";
    description = "Does something cool.";
    projectileEmoji = "⚡";
    pierce = 1;

    readonly stats = {
        damage: 20,
        cooldown: 1.5,
        area: 100,
        speed: 400,
        duration: 2,
    };

    constructor(owner: Player) {
        super(owner);
        this.baseCooldown = this.stats.cooldown;
        this.damage = this.stats.damage;
        this.area = this.stats.area;
        this.speed = this.stats.speed;
        this.duration = this.stats.duration;
    }

    // Override для evolved поведения:
    protected createProjectile(params: ProjectileParams): Entity {
        if (this.evolved) {
            return new MyEvolvedProjectile(...);
        }
        return super.createProjectile(params);
    }
}
```

**`ast-grep`** (`sgconfig.yml` → `tools/astgrep-rules/`) кодирует те правила
отсюда, которые являются **структурными паттернами кода**. До этого они держались
на моей памяти — и держались плохо: `fillText('💣')` прожил в покадровом рендере
месяцы, а пунктирное кольцо пережило три отдельных прохода «убрать UI с арены».
Каждое правило несёт в `note` историю: что именно сломалось и почему нельзя так
снова. Исключение помечается на месте — `// ast-grep-ignore: <id>` строкой прямо
над кодом, с объяснением **над** директивой.

Одно настоящее исключение зафиксировано в `no-ui-in-arena`: **телеграфы имеют
право выглядеть как UI**. Прицельное кольцо до удара — это инструмент, так и
задумано; кольцо вокруг того, что уже происходит, — декорация.

**`check-css-vars.mjs`** ловит кастомное свойство, объявленное не в `:root`, но
используемое в другой главе. Написан по следам реального бага: `--build-slot`
жил на `.build-panel`, а строка билда на экране смерти использует те же классы
снаружи — плитки схлопнулись в ноль, тесты и сборка были зелёные.

**CI:** пуш в `main` → `deploy-pages.yml` (тесты + сборка + GitHub Pages).
Сборка Android APK (`android-build.yml`) запускается **только вручную** через
вкладку Actions — чтобы каждый коммит не ждал Gradle.

## 📐 Coding Conventions

### Расчёт расстояний

**Используй утилиты из `core/Utils.ts`:**

```typescript
// ✅ Правильно: расстояние между двумя точками
import { distance } from '../../core/Utils';
const dist = distance(this.pos, enemy.pos);

// ✅ Правильно: длина вектора (magnitude)
const speed = Math.hypot(velocity.x, velocity.y);

// ❌ Неправильно: ручной расчёт
const dist = Math.sqrt(dx * dx + dy * dy);
```

**Когда что использовать:**

| Случай                           | Функция                |
| -------------------------------- | ---------------------- |
| Расстояние между двумя `Vector2` | `distance(a, b)`       |
| Длина вектора (speed, magnitude) | `Math.hypot(v.x, v.y)` |
| Нормализация вектора             | `normalize(v)`         |

### UI: пиксельная тема

`src/style.css` — **только список `@import`**. Сами правила лежат в
`src/styles/` по главам (`tokens`, `screens`, `buttons`, `cards`, `dev-mode`,
`hud`, `pause`, `level-up`, `result`, `build-panel`, `reroll`, `achievements`,
`records`, `options`, `joystick`, `responsive`).

> **Порядок импортов — это каскад.** Он повторяет порядок исходного файла, и
> ломать его нельзя: поздние главы намеренно перекрывают ранние, `responsive`
> идёт последним. Новая глава = решение, **куда** в каскаде она встаёт, а не
> «дописать в конец». Vite инлайнит импорты на сборке, рантайм не страдает.
> Проверка после любой перестановки — собрать и сравнить хеш `dist/assets/*.css`
> (при чистом переносе он не меняется вообще).

Токены — в `styles/tokens.css` (`:root`):

- Никаких скруглений и мягких теней. Рамки — `box-shadow: 0 0 0 var(--px) color`,
  глубина — жёсткие смещённые тени с `blur: 0`.
- Анимации короткие и «ступенчатые» (`steps()`, 90–300ms), не плавные фейды.
- Кнопки — только `this.createPixelButton()` из `BaseScreen` (он же вешает
  звуки `uiHover`/`uiSelect`).
- Текст на canvas — `drawPixelText()` из `core/PixelFont`, не `ctx.fillText`.
- Уважай `prefers-reduced-motion` (блок в конце style.css).
- **Размеры игрового оверлея — от вьюпорта, а не в px.** Панель билда задаёт
  одну переменную `--build-slot: clamp(34px, 3.6vmin, 58px)`, всё остальное
  (иконки, бейджи, отступы, ширина ряда) считается от неё. `vmin` берёт
  **меньшую** сторону экрана: ультраширокий монитор не раздувает элемент, а
  высокое окно не сжимает. Фиксированные px значат, что на 2K панель
  съёживается в точку — так и было до августа 2026.

### VFX оружий: правила производительности

1. **Никаких эмодзи в игровом рендере.** `ctx.fillText('🌀')` каждый кадр на
   каждой зоне — самый дорогой способ что-то нарисовать. Рисуй фигурами
   (`arc`, `fillRect`, полилинии).
2. **Запекай геометрию один раз.** Зигзаг молнии, спираль разлома, точки
   искр — считай в конструкторе (или раз в 0.05–0.1с), а не каждый кадр:
   иначе эффект «кипит» и жрёт CPU.
3. **Растягивай урон по кадрам.** Цепочка/залп, который наносит 20 ударов в
   одном кадре, даёт всплеск из damage numbers, партиклов и glow. Делай это
   через таймер (`hopInterval`, staggered `delay`).
4. **Бюджет партиклов.** У пресетов разная цена: `emitNuclear` ≈ 390 частиц,
   `emitOrbitalStrike` ≈ 165, `emitOrbitalImpact` ≈ 34. Для залпов бери лёгкие.
5. **`shadowBlur` — дорого.** Максимум один проход на эффект, не на каждый
   штрих.
6. **Иконки уникальны.** Панель билда — это ряд эмодзи и больше ничего, две
   одинаковые иконки там неразличимы. Тест `Powerups.test.ts` сторожит все
   оружия, эволюции и перки разом (ловил: 💣 граната/Цепная Реакция,
   ❄️ Frost Nova/Охлаждение, ⚡ молния/Разряд, ⏰ Time Shatter/Временной Поток).
7. **Никакого UI внутри арены.** Пунктирные кольца по краю зоны, индикаторы
   «вот где начинается эффект», подписи — это элементы меню, нарисованные
   поверх боя. Игрок и так читает цифры урона, полоску HP и тосты; кромка
   самой зоны уже говорит, где она кончается. Убраны: пунктир вокруг Fungal
   Bloom, пунктир у FrostZone, грибы в Spore Cloud, кольцо вокруг игрока при
   контактном уроне.

### Избегай дублирования

- **Не изобретай велосипед** — проверь `core/Utils.ts` перед написанием утилит
- **DamageSystem** — весь урон через `damageSystem.dealDamage()` (с `skipModifiers: true` для пре-калькулированного)
- **SpatialHash** — используй `levelSpatialHash.getNearby()` вместо итерации по всем врагам

## ⚠️ Важные правила

1. **Урон врагам — всегда через DamageSystem** — не вызывай `enemy.takeDamage()`
   напрямую. Урон **игроку** от контакта — через `resolveContact` +
   `player.takeContact`; `player.takeDamage` только для дискретных ударов
2. **Cooldown НЕ уменьшается при апгрейде** — только через powerups
3. **Эволюция = level >= 6** — проверяй `this.evolved`, не `this.level === 6`
4. **Статы оружия в конструкторе** — копируй из `this.stats` в свойства
5. **onSpawn/onDamage** — используй колбэки, не напрямую GameManager
6. **Пауза (Escape / кнопка `II` в HUD)** — `gameManager.togglePause()`.
   В состоянии `PAUSED` `Engine.loop` **вообще ничего не делает**: ни
   `clearRect`, ни отрисовки, ни `juice.update` — на канвасе остаётся
   последний кадр, поверх него DOM-оверлей. Музыка снимается с планировщика
   (`audio.pauseMusic()`) и продолжает с того же места. Ничего не рисуй в
   обход этой проверки.
7. **Язык игры — английский** — весь код, комментарии и строки на английском
8. **Коммиты на английском** — сообщения коммитов всегда на английском языке
9. **Git Flow** — используем conventional commits:
   - `feat:` — новая фича
   - `fix:` — исправление бага  
   - `refactor:` — рефакторинг без изменения поведения
   - `docs:` — документация
   - `test:` — тесты
   - `perf:` — оптимизация производительности
   
   **Формат:** краткий заголовок, пустая строка, тело с bullet points:
   ```
   refactor(damage): centralize damage calculation
   
   - Remove Player.getDamage() method
   - Add source property to Projectile and Zone
   - Update all weapon implementations
   ```

## 🤖 AI Development Guidelines

### Parallel Tool Calls
<use_parallel_tool_calls>
If you intend to call multiple tools and there are no dependencies between the tool calls, make all of the independent tool calls in parallel. Prioritize calling tools simultaneously whenever the actions can be done in parallel rather than sequentially. For example, when reading 3 files, run 3 tool calls in parallel to read all 3 files into context at the same time. Maximize use of parallel tool calls where possible to increase speed and efficiency. However, if some tool calls depend on previous calls to inform dependent values like the parameters, do NOT call these tools in parallel and instead call them sequentially. Never use placeholders or guess missing parameters in tool calls.
</use_parallel_tool_calls>

### Context Window Management
Your context window will be automatically compacted as it approaches its limit, allowing you to continue working indefinitely from where you left off. Therefore, do not stop tasks early due to token budget concerns. As you approach your token budget limit, save your current progress and state to memory before the context window refreshes. Always be as persistent and autonomous as possible and complete tasks fully, even if the end of your budget is approaching. Never artificially stop any task early regardless of the context remaining.
